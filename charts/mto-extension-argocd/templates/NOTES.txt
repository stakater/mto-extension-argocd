UNINSTALLING
============

A plain uninstall is now safe -- run it directly:

  helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}

The chart's RBAC is annotated `helm.sh/resource-policy: keep` (and, for GitOps,
`argocd.argoproj.io/sync-options: Prune=false,Delete=false`), so it OUTLIVES the
uninstall. That is what makes the single command work: dropping the parent
TemplateInstance lets template-operator-v2 reap the children and release their
AppProjects while the RBAC those finalizers depend on is still present. Without
the retained RBAC the finalizers deadlock in Terminating, which is why this used
to need an ordered manual dance.

What happens to the AppProjects this release manages depends on the operator
build and on onDeletePurgeAppProject. With the default (retain) on
template-operator-v2 8a44194 / v0.0.7 and later they are RELEASED and survive;
on v0.0.6 and earlier they are DELETED, because retain is not enforceable there.

The retained RBAC is deliberately left behind -- it is harmless once the
projects have drained, and it is re-adopted automatically on a same-name
reinstall. Remove it explicitly only when you want it gone:

  kubectl delete clusterrole,clusterrolebinding -l app.kubernetes.io/instance={{ .Release.Name }}
  kubectl delete role,rolebinding mto-extension-argocd-children \
    -n {{ .Values.operatorNamespace }}
  kubectl delete role,rolebinding mto-extension-argocd-integrationconfig-read \
    -n {{ .Values.integrationConfig.namespace }}

If you are reinstalling, wait for `Template/mto-argocd-parent` to disappear
first. `helm uninstall` returns before template-operator-v2 releases its
finalizer, and an install in that window fails with an ownership-metadata error
(TOV2-4).
